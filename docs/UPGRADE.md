# 已有实例升级

## 升级前

1. 记录当前镜像的固定标签 / 摘要。停止旧实例后备份配置和整个 `instance` 目录，包含 SQLite 数据库及可能存在的 WAL 文件。
2. 检查 `jwt_secret`：启用登录认证时必须为至少 32 字符的独立密码，不能保留示例值。
3. 检查每个监控的主备源站和检测方式。网站建议使用 HTTP/HTTPS；升级不会擅自把已有 Ping 策略改为 HTTP。

## 配置挂载

新 Compose 挂载整个配置目录，以便原子保存：

```yaml
volumes:
  - ./config:/app/config
  - ./instance:/app/instance
```

如果之前将 `./config.yaml` 单文件挂到 `/app/config/config.yaml`，先把配置复制到 `./config/config.yaml` 并更新挂载。单文件挂载可以读取，但 Linux 绑定挂载通常不允许原子替换该文件，界面保存会明确报错。数据库挂载路径保持原有位置。

## 行为变化

- **HTTPS 证书默认校验。** 旧版无条件跳过校验。源站使用自签名或 Cloudflare Origin CA 证书时，先在对应策略勾选允许该证书；普通公共 CA 证书保持默认即可。
- **主备地址必须明确且不同。** A / AAAA 检查地址类型；CNAME 使用独立的源站域名。旧配置不合法时会显示错误并停止该项切换，其他监控继续运行。
- **YAML 不再每次重启覆盖数据库。** 初始化标记存入 SQLite。已有数据库的界面配置会保留；删除最后一项后也不会重新导入 YAML。
- **状态含义变清楚。** `Down` 表示主备均不可用；`Failover` 表示当前使用非优先路径；`Error` 表示配置 / DNS 操作失败。请同时查看当前地址和主备健康字段。
- **定时切换保存优先地址。** 切到备用后继续检测备用，备用故障可回到健康的主地址，恢复后仍尊重计划设置的优先地址。
- **手动恢复失败返回错误。** 不会再把数据库伪装成“已恢复”。恢复目标必须通过健康检查。
- **HTTP 检查判断最终 2xx。** 只跟随同主机重定向；跨主机跳转请配置最终健康 URL。可指定 `expected_status`。
- **TTL 可提前设置。** 旧记录 `dns_ttl=0` 保留现值，新建策略界面默认 60。设置较低 TTL 后，需要等待原 TTL 窗口结束，再评估完整故障切换时长。
- **凭证引用受保护。** 使用中的账号不能直接重命名 / 删除；先在监控策略中重新指定账号。找不到账号不会静默使用其他 Token。
- **同一 DNS 名称 / 类型只允许一个策略。** 清理旧实例中互相竞争的重复策略。普通 DNS 编辑器拒绝修改已经由监控管理的记录，避免与自动切换竞争。

## 启动与检查

```bash
docker compose pull
docker compose up -d
docker compose logs --tail=100 cfguard
```

数据库自动添加新字段、索引和初始化标记。登录控制台，检查实际当前地址、两端健康、错误信息和定时目标。先用测试域名执行一次故障演练，再决定是否调整生产检测间隔。

回退时使用此前固定镜像和停机备份。不要同时运行新旧实例管理同一条 DNS 记录。
